### Goal

Replace the per-canvas undo footer with a root-wide Archive page that makes every archived or effectively hidden item findable and explains the canonical operation that can bring it back.

### Repository grounding

- `ArchivedRegionStore` reads one canvas and intentionally suppresses cascade members and independently archived children with archived parents. Reusing that query would miss the main requirement. Its presentation patterns (names, counts, pending controls and visible errors) are reusable; its direct-only state must go.
- `SectionService.restoreSection`, `TaskService.restore` and `ReflectionService.restore` already perform canonical undo. Section markers and task markers identify exact cascade membership. Project/ancestor guards already landed in 25.2. Do not rewrite these services unless a new failing conformance test proves a gap.
- `ProjectService.update` reactivates by explicit non-archived status and checks ancestors; `archive` refuses live direct children. Projects have no archive timestamp or prior-status field. Never present `updatedAt` as an archive time.
- `ProjectPageService.setEnabled` permits Archive enabling even on an archived root. Disabled owning pages still allow restoration. `PROJECT_PAGE_REGISTRY` currently renders Home and Todos; existing routes and page records need no expansion.
- `ProjectWorkspaceStore.root()` already resolves the root from a nested canvas. The shell supplies all seven `ProjectPageRenderer` inputs and stable callbacks. `restoreBlocked` includes optimistic header writes, not just archived status.
- Todos provides the repository-only projection, gateway, combined MCP permission and generation/write-epoch store examples. Its archived-root empty result is deliberately unsuitable for Archive.
- `remove_section` already archives through `SectionService.remove`; row archive/restore HTTP routes and gateways already exist. Project PATCH already handles archive/reactivation. Avoid duplicate endpoints for these writes.
- `ProjectPageStore` calls `shortcuts.list` from initial load, section refresh, shortcut refresh and reconciliation. The shell's `shortcutsAllowed` capability must govern every read path, including reconnect/reset, not merely the first load.

### Acceptance check

Parent **Done when**, verbatim:

> archive a nonempty section and a task with descendants, find both from root Archive, restore exactly the cascade members, and find/reactivate an archived subproject. Reload and repeat through MCP; no archive becomes unreachable when a tab is disabled. Permanent deletion and bulk restore remain deferred.

Make this executable with test-local fixtures on `nested-projects` (domain) and `agent-heavy` (browser/MCP), without changing distributed seeds:

1. Build a root, child and grandchild, duplicate section names, two task containers, and reflection containers on Home and a disabled Reflections page. Include another root and foreign workspace as exclusion controls. Archive a child task independently, then its parent with other live descendants; separately archive a populated section with pre-archived rows. Archive a reflection independently and a populated reflections section. Archive a leaf subproject containing live rows; archive its parent only after its children are archived.
2. Root Archive lists each `(kind, id)` exactly once, including every cascade member and previously archived child. It identifies canonical project/page/container, own archive cause, and current blocker. It lists live contents hidden by archived projects distinctly. A root archived in its own right can still query/open Archive and reactivate through its existing status control.
3. Restore the section and parent task through their canonical operations. Compare exact IDs, archive markers, content, task statuses/completion timestamps, ownership and page positions before/after: only cascade members return; independently archived rows remain listed and become eligible when their blockers return. Views have no fictitious owned-row count. Section restore appends on its original page only.
4. Reactivate ancestors in order with an explicitly selected status. No descendants change status automatically. Failed reactivation leaves all dependent controls blocked and shows an error. Independently archived work remains archived. Restoring content on a disabled owning page does not enable or relocate that page.
5. Disable Archive, reload its old URL, observe Home fallback/explanation, then use **Open archive** in View Mode from root controls and a nested canvas's navigation context. It enables the root's Archive and navigates only after success. Repeat for an archived root reached by its canonical URL. Failed enabling keeps location/state intact and permits retry.
6. Repeat the archive/query/restore/reactivation sequence with canonical MCP tools; verify HTTP and MCP return the expected IDs/causes/blockers, not merely mutually equal answers. Reload the page and restart the isolated acceptance host to verify persistence. Observe a descendant MCP restore updating the open Archive and work hierarchy without manual reload.
7. Ordinary live canvases omit archived sections/rows; Todos and Home shortcuts omit archived/effectively hidden source content, and shortcuts revive after canonical restore. Preserve the documented explicit-owner read exception for archived projects (§31): this slice does not blanket-hide direct archived-owner canvases.
8. Visit a work canvas, trigger a live refresh, reconnect/reset and a section mutation/reconciliation: no shortcut list call and no shortcut error. Home still loads placements and reports real failures.

### Proposed implementation

#### One shared read model

Create `ProjectArchiveQuerySchema = { projectId }` and `ProjectArchiveResultSchema = { projectId, root, items }` in `packages/contracts/src/project-archive.ts`. Reuse canonical `RootProjectSchema`, `SubprojectSchema`, `ProjectSectionSchema`, `TaskSchema`, `ReflectionSchema`, IDs, page kinds and permissions; infer types from Zod. `root` supplies archived-root context rather than duplicating the root as an item.

Items are discriminated by `kind: 'subproject' | 'section' | 'task' | 'reflection'`, carrying the matching canonical record, origin, cause and restoration state. Origin has project/page IDs, page kind/enabled state, root-to-owner `{ projectId, name }` breadcrumbs, and section ID/display name where applicable. No transport URLs or stored projection rows.

Keep **cause** separate from **current eligibility**. Cause is `own`, `section-cascade` with section ID, `task-cascade` with task ID, or `hidden-by-project` with project ID for an unarchived entity. Own archive state comes from `status === 'archived'` or `archivedAt`; cascade markers take precedence over `own` for rows. Preserve canonical timestamps as supplied; no synthetic project archive dates.

Restoration state is a schema union: `ready` (canonical operation and required write grant), `blocked` (typed project/section/task target with ID and display name), or `not-archived` (effectively hidden live item, no direct restore). For effectively hidden live items also include the blocking project target so the UI can explain the route out. Eligibility describes structural domain constraints, not a new authorization system; writes always enforce the actor's grants. The combined query requires all three read grants even for an empty archive.

`ProjectArchiveService.derive` depends on project/page/section/task/reflection repository interfaces only. Assert `projects.read`, `tasks.read`, `reflections.read` before content reads. Missing/foreign root gives not found; a same-workspace subproject gives a domain rule error. Resolve the full workspace project set including archived records, walk only the selected tree with visited sets, and read rows/sections with `includeArchived: true`. Filter membership before projecting content. Disabled/missing Archive tab does not restrict the query or create a page; an archived root still returns its tree.

Include all explicitly archived entities plus otherwise live entities hidden by an archived owning project/ancestor. Do not traverse shortcuts. Resolve archive blockers in actionable order: highest archived project ancestor first (including owner for content), then archived container, then highest archived task ancestor. A subproject's own archive is its action, not its blocker. Cascade cause still names the exact marker source even when a higher blocker must return first. Root blockers point to the root header; other targets identify an Archive entry. Recompute after every write. Do not invoke a write as a probe or add query-to-mutation-service edges.

Use stable ordinal ordering by owner project ID, kind (`subproject`, `section`, `task`, `reflection`), then entity ID; render breadcrumbs beside each item. This is deliberately not an invented archive chronology. Counts for an archived container count its exact `archivedWithSectionId` members, not independently archived rows; views show no count. Counts and state are derived, never persisted.

#### Canonical writes and transport parity

Add `GET /api/projects/:id/archive` and `gateway.archive.get(projectId)`, with one host-composed `ProjectArchiveService` also available to MCP. Add `get_project_archive` to page tools with `projects.read` and existing `additionalPermissions: ['tasks.read', 'reflections.read']`. Reuse existing metadata machinery; no protocol changes.

Add tools `archive_project`, `restore_project`, `restore_section`, `archive_task`, `restore_task`, `archive_reflection`, `restore_reflection`. Keep `remove_section` as the canonical section archive tool, clarifying its description; do not add an alias merely for symmetry. Project restore takes `projectId` and a required non-archived `ProjectStatusSchema` value, and delegates to `ProjectService.update`; document this as explicit status selection, not prior-state recovery. Define that reusable restore input in contracts, not a parallel tool/UI type. Existing project update remains supported. Permissions are projects.write for project/section actions, tasks.write for tasks, reflections.write for reflections. No additional read grant for a canonical write. Preserve activity attribution, transaction boundaries, idempotence/refusal differences and post-commit events.

#### Page, navigation and asynchronous state

Register `ArchivePage` as a renderer declaring all seven inputs. Provide `ArchivePageStore` locally. Adapt `ArchivedRegion` into a presentational list receiving shared archive items and emitting canonical action requests; remove its gateway-backed direct-only store. Display kind, label, origin, own/cascade/hidden cause, blocker guidance, exact section cascade count, explicit project status selector, and meaningful loading/empty/error/retry states. Navigation to a blocker stays in Archive (focus its entry). The root is not an entry: its guidance says **Use More project actions above to choose a non-archived status**. Test keyboard access to that existing button and its status choices; do not promise automatic focus into a closed menu or add renderer callbacks for it. Owning-page links use canonical routes/section fragments when live; a disabled or unbuilt Reflections owner is labelled honestly rather than promising a rendered container. Restoration itself never needs that renderer (25.7).

Restores/reactivations are awaited, like the existing undo footer, because a cascade cannot safely be painted as one removed row. Serialize writes within Archive, disable dependent controls during writes, preserve rows on failure, then requery on success and notify shell progress/hierarchy through existing callbacks. Honour shell `restoreBlocked` for content writes without preventing explicit root reactivation through the header. If the mutation succeeds but refresh fails, report refresh failure separately and retain a retry; do not claim the mutation failed. Keep potentially stale restore controls disabled until successful reconciliation.

Use PendingTasks, route generations, write epochs and DestroyRef cleanup as in Todos. Persona switching already reloads the application: use that teardown/reload boundary, not a new identity subscription. Invalidate on this root's events, reconnect and prototype reload. Discard reads already in flight when a write begins; defer new reads until settled. Old-root/persona/disposed success or failure cannot alter current rows/errors/pending controls or call shell callbacks. Header reactivation can optimistically change `restoreBlocked`; require a fresh Archive read after its pending interval before unlocking stale eligibility. Do not trust old eligibility after any failure or external mutation; canonical domain refusal stays authoritative.

Expose **Open archive** from the project More menu and the root navigation context visible on subprojects, independent of layout mode/tab visibility. Presentational components emit; `ProjectWorkspaceStore` awaits root `pages.setEnabled`, reconciles page context, and returns success; the shell navigates to `/projects/:rootId/pages/archive`. This reconciliation must be awaited and report success/failure: the existing fire-and-forget `refreshContext(): void`, which swallows read failures, is not sufficient. If enabling commits but the context read fails, stay at the current location, say **Archive was enabled, but navigation could not refresh**, and offer a read-only retry that reconciles context before navigating, without another toggle write. Protect context application against pre-toggle reads already in flight using a write epoch; stale snapshots cannot overwrite the reconciled enabled state. Already enabled is navigation without another toggle write. Guard duplicate clicks and stale navigation after root/persona changes; report actual toggle failures separately. Remove the footer only in the same green increment that installs these access paths.

Pass `shortcutsAllowed` to `ProjectPageStore.load`, store it with canvas context and guard all placement reads through one small local helper. Non-Home contexts return an empty placement list without calling the gateway; clear prior Home placements on route change. Apply the capability to load/refresh/reconcile/recovery and preserve it through internal reloads. Do not weaken `SectionShortcutService` or swallow valid Home failures.

### Boundaries touched and explicit non-goals

Components → feature store → gateway interface only; HTTP in adapter/host. Query uses repositories, never transport, JSON adapters or new service edges. Contracts defined once. Canonical mutations retain Clock/UoW/activity and post-commit events. Token-only styles; no global store, generic archive framework or new prototype flag.

No persistence migration, new repository/collection, copied ownership, new cascade, guessed prior project status, permanent deletion, bulk restore, reparent UI, cross-root shortcuts, editable shortcuts, reflection subjects/feed (25.7), showcase seeds/integrated polish (25.8), Calendar/Milestones/AI expansion or production infrastructure. Do not fix unrelated responsive-shell or failure-injection notes. Existing explicit-owner archive visibility exceptions stay intact.
