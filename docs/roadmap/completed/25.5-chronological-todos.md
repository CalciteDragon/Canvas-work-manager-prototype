## Outcome

**25.5, done.** A root's optional Todos page is the second entry in `PROJECT_PAGE_REGISTRY`, and
the first page that is a *projection* rather than a canvas. `ProjectTodosService.derive` walks one
root's tree, drops archived owners, ancestors, containers and rows, and returns the canonical
`Task` and `Subproject` records themselves under a shared discriminated union — one shape for the
page, `GET /api/projects/:id/todos` and `get_project_todos`. Completing a row calls the canonical
operation for its kind, so archive guards, activity attribution, completion timestamps and §39's
progress behave exactly as on the canvas that owns it; a completed unit of work does not complete
its children.

Three things the phase decided rather than inherited, all in
[the §78 entry](../../decisions/2026-09-todos-chronology-and-canonical-navigation.md). **Instants are
compared as text**: `IsoDateTimeSchema` accepts omitted seconds and a fraction of any length, so
`Date.parse` would call `.0001Z` and `.0009Z` one instant and sort them by id — a fixed-width
whole-second prefix plus right-padded fractions is lossless and needs no clock or timezone.
**Reading the chronology does not require the tab**: enabling a page is navigation state, not a
content permission. And **completion is one-way** — finished rows stay on the list with no control,
because reopening has no canonical operation that could know the previous status.

`WorkManagerTool` gained optional `additionalPermissions` for §54's rule that a derived page needs
the grant for each category it returns. The singular `requiredPermission` metadata key is unchanged
and a plural key carries the whole list beside it, so an existing client keeps working; the generic
contract suite now denies every tool once per declared grant rather than once in total.

Following a row's link had no mechanism: the app scrolls its own region and a canvas loads
asynchronously, so the router's global anchor scrolling cannot arrive at a section. The canvas
matches `#section-<id>` against the sections it actually loaded — never interpolating a fragment
into a selector — focuses the frame's heading once rendered, and opens a collapsed target through a
new `transientlyExpanded` input that leaves the canonical record alone. Arrival writes nothing;
collapsing the container releases the override through the ordinary canonical write. Watched in the
running prototype: the container opened, the heading took focus, and the stored section was still
collapsed afterwards.

The browser pass on `nested-projects` enabled Todos over the API, read the chronology through the
page, `GET /api/projects/:id/todos` and `get_project_todos`, followed a row into a collapsed
container, completed a task and a unit of work inline, and watched §46's failure injection refuse a
completion and roll the row back. Four friction notes came out of it, `note-2026-09-06-006`
through `-009`: one is this page's (a transiently opened container gives no sign of *why* it is
open), and three are things it made visible elsewhere — 25.4's shortcut error banner on every
sub-project canvas, the shell's columns not collapsing at 375px, and §46's failure rate applying to
reads as well as writes. The pre-run `.prototype/data.json` was restored afterwards.

Three review subagents read the diff. The one that mattered found a real hole: `invalidate()`
deferred *starting* a read during a completion, but a read **already running** when the click
landed still applied its pre-write snapshot on top of the settled row — the plan asked for
deferred *application*, and only deferred scheduling was built. A write epoch fixes it; a read
whose epoch is stale is discarded and re-read rather than painted. The same pass found that
`DestroyRef` was only unsubscribing the stream, so a completion resolving after teardown still
reported success and fired the shell's callbacks; disposal is now part of the store's one
staleness predicate. Both arrived as failing tests first. The reviews also caught an empty state
that contradicted §34 (undated work *is* listed), a vacuous e2e assertion, and that the journey
never asserted the acceptance's "focused and in view" — it does now, in the real browser.

Verified with `pnpm test` (186 contracts, 124 repositories, 94 seed, 373 domain, 102 MCP, 165
host, and 560 web tests), `pnpm lint`, `pnpm build`, `pnpm storybook:build`, and `pnpm e2e`
(3 passed, including the new `todos.spec.ts` journey). The production build's initial-bundle
warning is now 921 kB against the 850 kB warning budget, still below the 1 MB error budget.

## Implementation plan — Slice 25.5 — Chronological Todos

**Status:** done. Implemented, reviewed against the diff, and demonstrated in the running prototype and through both MCP transports. The Revisions section below records what implementation changed.

### Goal

Give a root project an optional Todos page that lists its tasks and every descendant work unit/task in one stable due-date chronology, with canonical navigation and completion.

### Spec sections

Implements §33–34, §45, §52–55 and §62–63; integrates with §19–23, §26–27, §31, §61 and §68–69. Preserves §38 Timeline scope and §39 progress formulas. Boundaries: §8–15, §21, §45, §70–71, §80. Closure: §77–79.

Read alongside [the parent roadmap](25-multi-page-projects-overhaul.md), [the settled product decision](../../decisions/2026-09-project-workspaces-and-subproject-work-units.md), and [UTC date-only due times](../../decisions/2026-08-task-date-only-due-time.md).

### Repository grounding

- `ProjectPageService` already creates/toggles optional page records. `PROJECT_PAGE_REGISTRY` advertises Home only; its registration drives the shell, Add page menu and enabled-page resolution. No new route or page persistence is needed.
- `ProjectPageRenderer` requires **all seven inputs**, including stable callback inputs, because the shell uses `NgComponentOutlet`. Todos must declare them even where canvas layout inputs are unused. It provides its own store; it must not reuse the page canvas's `ProjectPageStore` or source task-list stores.
- Tasks carry `projectId` and `sectionId`; sections carry `pageId`. `SubprojectSchema` and `TaskSchema` already hold canonical statuses and timestamps. `tasks.complete`, `tasks.update` and `projects.update` already own mutation semantics.
- `archivedAncestry` takes the complete workspace project set, including archived projects. `isHidden` alone is insufficient: it deliberately excludes projects archived in their own right. The new query must check both own archive status and archived ancestry.
- `TimelineService` supplies a useful repository-only projection pattern, but its date-range and sorting rules are not Todos rules. Neither Timeline nor Progress needs rewriting.
- UTC date-only controls store task due dates at `23:59:59.999Z`; `IsoDateTimeSchema` permits omitted seconds and arbitrary fractional precision. `Date.parse` loses sub-millisecond differences. Compare normalized UTC strings losslessly, not raw text, epoch milliseconds or browser-local dates.
- MCP's `WorkManagerTool.permission` and transport metadata currently express one grant; the generic contract suite assumes that one grant suffices. This slice is the first combined page query, so declaration, discovery and permission tests need an explicit pair without moving enforcement out of the domain.
- Canvas markup has `data-section-id`, but no router-fragment handling. A URL alone cannot prove arrival at an asynchronously loaded, possibly collapsed container. Add narrowly scoped canonical section targeting with the Todos links.
- Existing navigation/shell tests use Todos as their unbuilt-page example. Replace those examples with Archive and add positive Todos coverage.

### Proposed implementation

#### Shared read contract and domain query

Add `ProjectTodosQuerySchema = { projectId: ProjectIdSchema }` and `ProjectTodosResultSchema = { projectId, items }` in `packages/contracts/src/project-todos.ts`. Items are a Zod discriminated union:

- `kind: 'task'`, `task: TaskSchema`, and `origin` identifying owning project, page and section.
- `kind: 'subproject'`, `project: SubprojectSchema`, and `origin` identifying that work unit's own work page.

Derive types with `z.infer`; reuse existing schemas for records, IDs and page kinds. Origin includes `projectId`, `pageId`, `pageKind`, a root-to-owner breadcrumb of `{ projectId, name }`, and (task branch only) `sectionId` and section display name. Keep route strings out of domain results. No stored Todos collection, copied persistence rows, schema-version bump, new repository, or generic projection framework. Returning canonical records in a transient read result is not creating duplicate ownership.

`ProjectTodosService.derive(actor, projectId)` depends only on `ProjectRepository`, `TaskRepository`, `SectionRepository` and `ProjectPageRepository`. Check `projects.read` **and** `tasks.read` before content reads. Resolve the selected root in the actor's workspace; missing/foreign ID returns `EntityNotFoundError`, a same-workspace subproject is a `DomainRuleError`. An archived root returns an empty result, matching the exclusion rule, without leaking its hidden content.

Read the full workspace project set once, compute archived ancestry and walk the chosen root tree with a visited set. Exclude own archived status and archived ancestry before projecting. Fetch only tasks of included owners (or read/filter once in this in-memory prototype), join canonical sections/pages, and exclude archived tasks and sections. Derive origins from the canonical ownership chain; do not traverse shortcuts. Validated persistence guarantees task-parent archive cascades and ownership agreement; tests use real canonical archive writes plus fixtures for live descendants beneath archived project ancestors.

The query does not require a Todos page record or enabled tab: enabling is navigation state, not a content permission. Reads never create a page. Home/work are the only task-capable pages today and cannot be disabled, so every valid task origin is navigable; do not invent hidden task-page behavior for future page kinds.

For comparison, use a task's `dueAt` instant and map a subproject's `targetDate` to `${targetDate}T23:59:59.999Z`. Normalize each schema-valid UTC value to its fixed-width whole-second prefix (omitted seconds become `:00`) plus a fractional digit string (absent fraction is zero). Compare the prefixes ordinally, then right-pad the two fractions with zeroes to equal length and compare ordinally; this preserves arbitrary fractional precision and equates `.1` with `.100`. No `Date` construction, `Date.parse`, ambient timezone or clock is needed. Keep this small pure comparator private to the query service; no date-library framework. Undefined dates sort last; compare kind and IDs with explicit ordinal comparison, not locale collation. Display task dates as the first ten ISO characters and subproject dates verbatim. No local timezone conversion.

#### Transport and permission discovery

Expose `todos.get(projectId)` on `WorkManagerGateway`, backed by the HTTP route above. Compose `ProjectTodosService` in the existing host factory and MCP test harness; use that same service via `WorkManagerServices.todos`. `get_project_todos` lives in `tools/project-pages.ts`, uses the shared query schema and explains scope, retained terminal statuses, chronology and both required reads.

Extend `WorkManagerTool` with optional `additionalPermissions: readonly AgentPermission[]`, keeping the existing `permission` field compatible. Todos declares `permission: 'projects.read'` and `additionalPermissions: ['tasks.read']`. Preserve existing singular transport metadata and add a plural required-permissions metadata key with the complete list. Use the same list for discovery and generic test setup; domain `assertPermitted` remains the only enforcement. Test omission of **each** required grant, including projects-read-only and tasks-read-only agents; never return a partial answer. Do not add grants or alter existing tools' authorization.

#### Renderer, canonical navigation and completion

Register Todos beside Home. Build a simple semantic list showing type, title/name, due date or “No due date”, status, origin breadcrumb and a canonical link. Loading, empty, load-error/retry and write-error states are explicit. Native labelled completion controls work by keyboard; cancelled tasks retain their status with no completion control. Done/completed rows remain visible; reopening uses their canonical canvas controls rather than inventing a prior-status toggle on this page. No drag/drop, creation, title editing, filters, drawer or section-layout controls in this slice.

For unfinished tasks, call `gateway.tasks.complete(id)`; for unfinished subprojects, call `gateway.projects.update(id, { status: 'completed' })`. Apply optimistic status only, preserve original records for rollback, and reconcile with the returned canonical record, including its timestamp. Never fabricate `completedAt` in the UI. Disable repeat completion for a pending row and honor the shell's `restoreBlocked` input as a write freeze. On success call the shell's stable data-change callback; for subproject completion also call the hierarchy callback. Existing shell live handling keeps root record/progress/tree synchronized.

Task links use `/projects/:ownerId/pages/home#section-<id>` for root-owned tasks and `/projects/:ownerId#section-<id>` for subproject tasks. Subproject rows link to `/projects/:id`. Add a DOM ID at the **canonical section wrapper** and make its existing frame heading programmatically focusable, plus canvas-local fragment handling that waits for matching page data and rendered DOM. A collapsed target is expanded transiently for this visit without a layout write. Give `ProjectSectionFrame` an optional transient-expansion input; compute effective collapse consistently for content, class, ARIA and button behavior without replacing the canonical section object passed to its content store. Navigating to another target/page clears the override. An explicit collapse click releases that override and uses the existing canonical collapse operation; arrival itself writes nothing. Only match known sections in the loaded page, never interpolate a raw fragment into a selector. Missing targets leave the canvas usable with an explanatory notice. Do not enable global anchor scrolling: the app has its own scroll region and asynchronous canvases.

#### Store lifetime, failure and live refresh

Provide `TodosPageStore` on the renderer; inject only gateway/live interfaces and Angular lifecycle helpers. Keep query result, loading/error state and pending completion state local. Track async work with `PendingTasks`, following adjacent stores. Root/page changes clear old content immediately and advance a generation; every read/write continuation checks root, generation and disposal before touching UI or firing callbacks.

Subscribe through `LIVE_UPDATES` and unsubscribe on destroy. Refresh on events with `rootProjectId` matching the selected root (or direct `projectId` matching it), including task, project and section changes affecting dates, status, archive visibility or origin names. Recover on reconnect. `prototype.reloaded` (seed/reset/clock) clears content, advances generation and reloads even if the project ID is unchanged. Persona selection already performs a full browser reload through the prototype panel; it is not a new live-event kind and requires no identity subscription here. Unrelated roots do not refresh Todos.

Coalesce refreshes while a read is running; queue one more if invalidation arrives mid-read. During pending mutations defer read application and queue reconciliation, so an old response or the mutation's own pre-response event cannot overwrite the optimistic state. Serialize completion writes within the store for a bounded first implementation; other rows' controls are disabled while a write is pending. Once the write settles, perform the queued canonical read. A rejected read reports a refresh error and offers retry; it must not undo a successfully persisted completion. Route changes/destruction make old writes inert in this view even though an already-sent canonical mutation may finish.
