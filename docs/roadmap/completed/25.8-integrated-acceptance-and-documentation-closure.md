### Repository grounding

- The feature stack is implemented and has focused coverage. `apps/e2e` now has five isolated
  journeys: the original first-milestone browser path, MCP live task creation, and separate Todos,
  Archive and Reflections journeys. The latter three construct their own data over `agent-heavy`;
  the integrated 25.8 browser/MCP journeys now also prove that the committed showcase seed works as
  one whole product.
- At phase start, `nested-projects` had only canonical Home/work pages, an empty `sectionShortcuts`
  collection, three ordinary tasks, one unlinked reflection, and no archived-ancestor or
  equal-date case. `seeds.test.ts` explicitly reserved the empty shortcut collection for 25.8.
  The builder in `packages/prototype-data/src/seeds.ts` remains authoritative; the JSON file is a
  committed exact serialization checked by the seed suite, and now contains the integrated cases.
- At phase start, `ProjectPageService`, HTTP/MCP page operations and the Angular gateway already supported optional
  page toggles. The human UI did not: `ProjectPageNavigation` only rendered enabled page
  definitions, and `ProjectWorkspaceStore` had an Archive-specific enable/reconcile path solely
  for **Open archive**. 25.8 added the root-scoped manager, disabled-route re-enable action and
  generalized reconcile seam required by the parent journey.
- The page-management UI belongs in the root's project navigation column: the setting controls
  which entries that column shows, is independent of the routed child work unit, and must remain
  available in View Mode. Home is displayed as fixed; Todos, Archive and Reflections are toggle
  controls. A disabled-page fallback reuses the same operation to enable the requested kind and
  navigate only after fresh context reconciliation. When the route names a subproject, the
  manager remains visible because the column is still the root's, but it can configure only that
  root's optional pages and never the subproject's work canvas.
- `ProjectWorkspaceStore.openArchive()` already contains the important mechanics for a page
  toggle: pending suppression, write epochs, post-write context reconciliation, stale route/root
  protection, and a separate retry when the write committed but the read failed. Generalize that
  seam rather than adding three independent optimistic paths. **Open archive** continues to work
  when the manager is closed and for archived roots; it is not replaced by the manager.
- Client-side failure injection lives in `PrototypeWorkManagerGateway`, not the host. A browser
  can deterministically set 100% only after the page has loaded, trigger one optimistic write,
  observe rollback, then restore 0%. HTTP and MCP calls intentionally bypass that injection.
  Permission refusals must therefore be driven through agent grants, not described as injected
  transport failures.
- At phase start, existing page and shortcut stories covered many static states, but only
  `ProjectCanvas` had a `play` interaction. Storybook has no Vitest browser addon by decision;
  25.8 added decision-bearing plays and manually exercised them in the workbench, while

- At phase start, `docs/guides/mcp-setup.md` correctly said thirty-three tools; the first-milestone

### Acceptance check

Parent executable acceptance journey, verbatim:

> load realistic seed → create root → verify mandatory Home → enable optional pages → create
> subproject and nested subproject → edit description/due date → add each existing section kind
> to Home and a work canvas → add cross-page and nested-source shortcuts → verify chronology →
> complete task/subproject and reflect → archive/restore section/task/subproject → hide/re-enable
> pages → reload → perform equivalent key MCP mutations and watch browser refresh. Repeat key
> writes with injected failures and alternate persona/denied grants. All source data remains
> singly owned.

Made concrete at two levels so automation proves integration without pretending to replace
§77's design evaluation.

#### Automated, seed-backed browser/MCP acceptance

1. Seed `nested-projects` into Playwright's isolated data file and pin the clock. Assert the
   committed root has Home plus enabled Todos, Archive and Reflections, a depth-three work tree,
   a mixed Home canvas, and canonical page/work routes after reload.
2. Create a second root through the browser. Assert it owns and advertises only mandatory Home.
   Use **Manage pages** to enable Todos, Archive and Reflections; disable and re-enable Todos;
   reload after each settled state and prove the records and visible tabs agree. Visit a disabled
   Reflections URL and use its one-click re-enable action. On a subproject, assert the still-visible
   manager changes the root's page records and offers no control for the work canvas.
3. Return to the seeded root. Assert the seed's Todo rows have the exact expected order: dated
   work first, an equal instant resolved by kind then ordinal ID, completed/cancelled retained,
   and undated work last. Follow a nested task to its canonical work canvas/container.
4. Assert Home shows a nested-source shortcut beside owned sections. Complete the source task
   from Todos and observe the shortcut refresh without reload. Remove only the placement, then
   compare API snapshots: the source section and its rows are byte-for-byte unchanged and no
   extra task/reflection row was created.
5. Complete one seeded task and one nested subproject, create subject-linked reflections, and
   assert the root journal shows them with existing general entries and canonical origins. Reopen
   one subject and prove the reflection remains. Use explicit IDs/order, not only visible counts.
6. Archive and restore a task and a populated section from the root Archive page; reactivate the
   seeded archived subproject using an explicit status and prove its effectively hidden descendant
   returns. Independently archived rows stay archived. Reload and re-read the same IDs.
7. After a successful page load, set gateway failures to 100% through the development panel.
   Trigger one representative optimistic task completion and one optional-page toggle; the task
   reverts, while the deliberately non-optimistic page control keeps its last confirmed state.
   Both report the refusal and leave persisted state unchanged. Restore failures to 0% and retry
   successfully so the rest of the run is deterministic.
8. Switch to Alex through the prototype persona control and assert the seeded root is absent;
   switch back and recover the same route/state. This is workspace isolation through the actual
   identity reload, not a CSS visibility assertion.
9. Keep the browser open on each affected aggregate in turn and use a real Streamable HTTP MCP
   client to: add a nested task, move its due date, add/remove a Home shortcut, complete the task,
   attach a reflection, archive/restore it, and toggle an optional page. After every mutation,
   observe the relevant browser surface update through §62 without `page.reload()` and verify the
   mutation through its canonical HTTP read. Assert the successful writes' activity actions and
   Claude attribution rather than treating visible content alone as §57 coverage.
10. Narrow the existing read/write connection via the prototype agent-connection API and call
   `get_project_todos`, `get_project_archive` and `get_project_journal` once for each missing
   declared grant. Each returns an MCP error with no partial structured content and no mutation,
    while a foreign root is indistinguishable from a missing one. Restore the original grants and
    prove a permitted call still succeeds. The read-only token continues to reject writes.

`web.spec.ts` owns steps 1–8. `mcp.spec.ts` owns all of steps 9–10, including opening its own
browser page, waiting for that page's SSE handshake, making the MCP call and observing the update
in the same Playwright test/context. The focused `todos.spec.ts`, `archive.spec.ts`
and `reflections.spec.ts` stay independent and continue to prove their deeper cases; do not copy
their full fixture setup into the integrated journey.

### Proposed implementation

#### 1. Close the page-management acceptance gap

Add a presentational **Manage pages** disclosure to `ProjectPageNavigation`. It receives the
root's actual page records/capabilities, renders Home checked and disabled, and emits requested
optional-kind state changes. It neither injects a gateway nor decides routing. Disable all
optional controls while a page write/reconciliation is pending; retain the last confirmed state
until success rather than painting a navigation tab whose route is not yet safe.

Generalize the Archive-specific context write in `ProjectWorkspaceStore` into a typed optional
page setter over the contract's navigable optional kinds. Preserve the existing write epoch,
route/root guards, committed-write/read-failure distinction and retry semantics. Archive's
`openArchive()` becomes a small caller of that seam and retains its archived-root reachability.
The shell owns navigation after success. `resolveProjectPage` returns the validated disabled
optional kind on that redirect, and the shell carries it in navigation state alongside the notice,
so the short Home route still knows which exact page it may re-enable. Unknown, unbuilt, Home,
work and every subproject request carry no enable action. Home and work are never passed to
`setEnabled`.

Render the page manager's pending and failure text beside the controls; keep the existing header
write-error region for project-record writes and **Open archive** failures. No new product
page/domain/MCP contract was needed; the only contract change is the bounded notes-schema
compatibility correction recorded above, with a focused parser test. Record the page
manager placement and non-optimistic tab rule in a §78 decision because both are product choices,
not merely wiring.

#### 2. Turn `nested-projects` into the integration showcase

Change only the builder, then regenerate `prototype/seeds/nested-projects.json` as its exact
pretty-printed serialization. Keep the six seed names and other five snapshots unchanged.

The root owns enabled Home, Todos, Archive and Reflections records. Preserve a depth-three live
branch and the deliberately empty work canvas as an empty-state fixture. Add a separate archived
intermediate subproject with a live descendant to exercise effective hiding/recovery; document in
the builder that this valid persisted state represents historical data and cannot be newly
created by the current archive command while a live child exists.

Add:

- descriptions and a mix of dated/undated/completed subprojects, plus completed and cancelled tasks;
- task due times deliberately inserted out of order, including an equal instant across a
  date-only subproject and task, plus undated/completed/cancelled and independently archived rows;
- every section kind across the root Home and one live work canvas, with stable explicit names;
- an owned Reflections-page container, general reflections on more than one canvas, and linked
  reflections for a completed task and completed subproject;
- Home shortcut placements to a nested Task List and to a section on another root page, retaining
  canonical ownership and same-root identity; and
- archive fixtures with explicit own/cascade/hidden causes sufficient to exercise guidance
  without corrupting integrity; and
- the existing read/write and read-only agent connection IDs expected by the fake tokens, with
  the exact projects/tasks/reflections grants the integrated success and denial cases manipulate;
  and
- one Alex-owned root as the foreign-but-existing control. Extend the existing `project()` helper
  with an optional workspace ID rather than hand-building a parallel project shape; seed tests pin
  the foreign ownership and both token-backed connection identities.

Every helper accepts the new optional fields rather than bypassing Zod. Seed tests assert IDs,
ownership, ordering inputs, page capabilities, shortcut source identity, reflection subjects,
archived ancestry and `InMemoryDataStore` integrity. They do not duplicate the projection
services' exhaustive behavior matrices.

#### 3. Add the integrated Playwright paths

Extend `apps/e2e/seed.ts` with narrowly shared persona-aware JSON request helpers and a real MCP
client factory used by the two changed specs. Keep `seed()` and `setClock()` unchanged and do not
refactor the three focused feature specs merely to remove their local helpers.

Keep one coherent seed-backed happy-path test in `web.spec.ts`, then put deterministic injected
write failures and persona isolation in separately reseeded tests. In `mcp.spec.ts`, keep the live
mutation/browser observation together, but put the table-driven grant matrix plus read-only and
foreign-scope refusals in its own reseeded test. Every test pins the clock. Failure settings and
mutated connection grants are restored in `finally`, even though the next test also reseeds.
This preserves the integrated journey while ensuring one late failure does not hide every later
claim. Wait for the SSE handshake before the first MCP write, assert expected IDs/content after
each event, and never use browser reload as a live-update wait. Use accessible roles/text where
stable and existing `data-*` hooks only where identity is otherwise ambiguous.

The Playwright data file remains `.prototype/e2e-data.json`; no test writes the live store.
Permission cases mutate the fixture's connection grants through `/api/agent-connections/:id`,
snapshot activity after each grant setup, restore the grants in `finally`, and compare both the
MCP error and post-call canonical state. The grant edit's own activity is not miscounted as an
effect of the denied read.
