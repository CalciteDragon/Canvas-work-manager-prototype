## Your scope

All 194 matrix cells in `apps/e2e/ux-output/37dd16e2303e7d8968905de74767710d6b02b85c/` (`index.json` lists them: six seeds, both themes, 1440/1024/375 as the

## Your lens: consistency

The same thing looking and behaving the same everywhere: buttons and icon buttons, menus, headers,
section chrome, rows, cards, dialogs, empty and error sentences, spacing, radii, type sizes and
weights, icon style, wording of the same action in different places. Compare like with like across
surfaces, themes and widths; name both places in every finding (`heuristic`: internal consistency, A
vs B).

**Values that escape the design tokens.** Run exactly this one command from the repository root and
read nothing else of the stylesheets (common.md § 2):

```bash
grep -rnE --include='*.scss' '#[0-9a-fA-F]{3,8}\b|rgba?\(|hsla?\(|[0-9.]+(px|rem|em|ms|s)\b' apps/web/src | grep -v '^apps/web/src/styles/_tokens.scss:' | grep -vE '^[^:]+:[0-9]+:[[:space:]]*(//|/\*|\*)' | sed -E 's#[[:space:]]*//.*$##; s#/\*.*\*/##g'
```

It prints only lines with a literal colour, length or duration outside the token file, with comments
removed. A literal is a finding only when it shows: a visible inconsistency you can point to in a
capture (cite the capture and the line). Hairlines (`1px`), zero values and breakpoint definitions are
expected.
